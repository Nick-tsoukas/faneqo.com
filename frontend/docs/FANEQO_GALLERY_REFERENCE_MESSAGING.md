# Faneqo Gallery-Reference Messaging

Updated 2026-08-30.

## Product promise

An artist can choose a published show gallery while writing a direct message. The fan receives a rich gallery card inside the private conversation, can open the protected photos, save the same night to FanPassport, and share its protected Faneqo link.

## Canonical ownership

- `ArtistUpdate` remains the only gallery and media owner.
- `ConversationMessage` carries a durable server-generated reference plus optional message text.
- `passport-gallery-save` stores only the fan’s authorized `artistUpdateId` reference.
- Strapi Upload/private S3 remain file truth.
- No media is copied into the DM or FanPassport.

## Send authorization

The backend accepts `artistUpdateId` only through the authenticated conversation send action. Before persistence it requires:

1. the sender is the band side with `sendFanMessages`;
2. the gallery is published, has photos, and has show context;
3. the gallery belongs to the same band as the conversation;
4. the recipient fan account can currently access the gallery;
5. the payload is a gallery reference or new photo attachments, never both.

The reference envelope is reserved and generated by the server. User-authored text containing the reserved marker is rejected.

## Read authorization

Every conversation/detail or message-window read:

1. extracts referenced `artistUpdateId` values;
2. resolves them in one bounded batch;
3. reuses the existing Artist Update access service;
4. returns full gallery presentation only when the current viewer is still authorized.

If access is revoked, the message remains in the conversation but becomes a locked placeholder with no title, show metadata, or media URLs.

## Frontend flow

- The gallery button appears only in the artist composer.
- The picker lists published, show-scoped, non-empty galleries from the current band.
- Selecting a gallery shows its rich preview before send.
- The sent card previews up to four photos while preserving the real gallery photo count.
- Fans can open the gallery, save it to FanPassport, and invoke the native share sheet or copy the protected link.
- Artists can open the card’s gallery lightbox from the same thread.

## Explicit exclusions

- no schema migration;
- no `MediaAsset`, second gallery, or copied media array;
- no public Artist Updates section;
- no gallery reference from a fan to an artist in V1;
- no attendee-only access granted by possessing a message;
- no public fallback for protected media;
- no engagement score, rank, or badge.
